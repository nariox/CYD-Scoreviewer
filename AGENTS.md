# AGENTS.md — CYD Basketball Scores

ESP-IDF + LVGL 9 embedded C project for CYD2USB (ESP32, ST7789 320×240).

## Commands

Source ESP-IDF first: `source /opt/esp-idf/export.sh`

```bash
cd cyd_basketball_scores
idf.py set-target esp32
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor
```

Clean build: `idf.py fullclean` (removes `build/`, `managed_components/`, `.cache/`).

Soak-test the score feed (short refresh interval, watch the heap/lv-pool logs):

```bash
idf.py -DCYD_NBA_REFRESH_S=45 build && idf.py -p /dev/ttyUSB0 flash
idf.py -DCYD_NBA_REFRESH_S= build            # back to the 15-minute default
```

Exercise the pager without touching the screen (the worker walks a few pages deeper each
cycle, then snaps back to the newest):

```bash
idf.py -DCYD_NBA_AUTOPAGE=1 -DCYD_NBA_REFRESH_S=45 build && idf.py -p /dev/ttyUSB0 flash
```

Exercise the card-tap → detail paths the same way (the worker opens the detail view
for the newest game once, so the pool handover and the re-render on the way back get
logged without a finger on the glass):

```bash
idf.py -DCYD_NBA_AUTODETAIL=1 -DCYD_NBA_REFRESH_S=45 build && idf.py -p /dev/ttyUSB0 flash
```

Exercise the tab switch + college pre-warm the same way (after the first cycle the
worker hops to NCAA and back, so the instant-paint path and the slate re-anchor get
logged without a finger on the glass):

```bash
idf.py -DCYD_NBA_AUTOTAB=1 -DCYD_NBA_REFRESH_S=45 build && idf.py -p /dev/ttyUSB0 flash
```

Level 2 is the race soak: an `esp_timer` queues `set_league(NCAAB)` 15 s after the
worker starts — right in the middle of the first balldontlie fill, the interleaving
that used to mix two leagues on one board. Expect
`league switch pending - dropping the half-finished page` → `switching feed to NCAAB`
→ boards that only ever show one league:

```bash
idf.py -DCYD_NBA_AUTOTAB=2 -DCYD_NBA_REFRESH_S=45 build && idf.py -p /dev/ttyUSB0 flash
```

Stress the TLS stack (the diagnostic that pinned the "cert storm" to ESP-side
heap: alternating ESPN/Google HEAD handshakes, logging free heap + largest block
per probe until the allocator gives up — expect the first fails around ~45 K
free heap. CAVEAT: HEAD probes exercise the handshake only — Akamai's GET bodies
need the full 16 KB IN buffer, see Lessons):

```bash
idf.py -DCYD_NBA_TLSSTRESS=300 build && idf.py -p /dev/ttyUSB0 flash
idf.py -DCYD_NBA_TLSSTRESS= build            # clear the cached hook after
```

Adopted shape (2026-10, device-proven — see `tools/mbedtls_opt/README.md`): **3 cards per
page** (154 px inside the 164 px band — a page never scrolls), 12-game boxes/snapshots,
48 KB LVGL pool, 44 KB mbedTLS arena — all of it are plain-build DEFAULTS. Override knobs:
`idf.py -DCYD_NBA_PAGE_SIZE=8 build` (cards cost ~2.6 KB LVGL pool each: 8 needs the pool
back at ~64 or the render sits at ~99%), `-DCYD_NBA_BOX_GAMES=N`, `-DCYD_NBA_PERSIST_GAMES=N`.
Opt out of the arena (stock allocator, floors active again, pool back to 64 via sdkconfig):
`idf.py -DCYD_MBED_ARENA_KB= build`.

Exercise the college feeds without a finger on the tabs (start straight on WNBA=1 / NCAA men=2 /
NCAAW=3 (WNBA needs no day shift in October — the playoffs are live), and anchor the feed's "today" N days off the real one — college is in the
off-season in October, so shift onto a January slate to see real games/logos):

```bash
idf.py -DCYD_TEST_LEAGUE=2 -DCYD_TEST_DAY_SHIFT=-266 -DCYD_NBA_REFRESH_S=45 build && idf.py -p /dev/ttyUSB0 flash
idf.py -DCYD_TEST_LEAGUE= -DCYD_TEST_DAY_SHIFT= build   # back to production
```

NOTE: `idf.py` caches `-D` options in `build/CMakeCache.txt` — a plain
`idf.py build` after a test build **keeps flashing the hooks**. Clear them with
the empty `-DVAR=` form above.
NOTE: any `target_compile_definitions` value containing parentheses must be **quoted** in
`main/CMakeLists.txt` — CMake splits `(45*1000)` as list syntax and the build dies in the
shell with a stray `-D)`.

## Architecture

- **Entry point**: `main/app_main.c` — creates all screens, wires navigation, starts LCD + touch
- **Screens** (all created in `app_main.c` as static globals):
  - `splash_screen` — splash with spinner, 3s one-shot auto-transition, plus a boot stage line (`splash_screen_set_status` / `splash_screen_is_current`, ASCII text under the subtitle: connecting Wi-Fi / stored scores / fetching first scores)
  - `cards_screen` — league tabs (`NBA | WNBA | NCAA | NCAAW`, lit tab = active feed; clickable labels sized per label via `lv_text_get_size` + `UI_TAB_PADX`, sharing one static `lv_style_t` — lv_btns cost two widgets each) + Wi-Fi badge (native `LV_SYMBOL_WIFI`: black = connected, an `LV_SYMBOL_CLOSE` child in the header colour cuts it = off, blinking grey = connecting) + date pager strip + card list (3-card page = 154 px inside the 164 px band — never scrolls); tapping a card opens the game detail view
  - `game_detail_screen` — box score by period + team names + tip-off + venue (**built on the first tap and freed again on the way back**, not at boot: the card page is dropped while it is open, see the pool note in README). Per league: NBA/NCAAW play quarters (`Q1..Q4`), NCAAB plays halves (`H1 H2`) — the OT column sums whatever period slots sit beyond the league's regulation count; timeouts row is NBA-only (ESPN doesn't carry them). Venue row (arena, +", City ST" for college) between the date line and the live line — hides when unknown and the footer collapses back to two rows
  - `settings_screen` — brightness slider (NVS-persisted), Wi-Fi/nav buttons, calibration button
  - `wifi_screen` — Wi-Fi config UI (scan/connect/save, wired to `wifi_backend`)
  - `touch_test_screen` — 9-button touch test (**not created at boot any more**: every screen costs LVGL pool; build it in only when debugging touch)
  - `calibration_screen` — 4-point crosshair touch calibration with long-press undo, wired into boot flow
- **Score data — ALL FOUR LEAGUES**: `espn_api.c/h` — ESPN site scoreboard client (`site.api.espn.com/.../{nba,wnba,{mens,womens}-college-basketball}/scoreboard?dates=YYYYMMDD`, no key, needs `User-Agent: Mozilla/5.0`; balldontlie + cJSON are **retired** — the pro scoreboards carry more than balldontlie ever did: per-period stats AND the venue, on ESPN's no-quota polite access). College caveat kept: ESPN serves only the ~10-19 network-covered D1 games/day (60+ in November) — not the full D1 slate. The body pads each event to ~20 KB (200-400 KB/day), so **no cJSON tree anywhere**: a constant-memory streaming scanner (`espn_parse_scoreboard`, brace-depth + container name/key tracking) assigns values only at the schema points the board renders (ids, dates, status, linescores, `competitions[].venue`), keeping each day's **24 newest** games (ESPN orders events oldest-tip-first — a plain cap keeps the wrong half of a busy day). `.date` is the **US game day** (event stamp − 12 h, the same rule as `time_sync_game_day_epoch`) — a UTC-prefix copy once dated tonight's late tips as tomorrow, and `tools/sim` now asserts the rule per fixture against glibc `timegm`. One request per day, `ESPN_API_MIN_GAP_MS` (4 s) pacing, **one TLS handshake per burst**: a persistent keep-alive `esp_http_client` (the feeds are all one host) is reused across a day-walk/slate-hunt/pre-warm chain via `esp_http_client_set_url`, and `nba_service` calls `espn_api_conn_release()` before every sleep so an idle session never parks ~20 KB across the refresh gap (a transport failure tears the client down too — the next request starts from scratch; an idle gap > 55 s rebuilds it as belt-and-suspenders). Host-tested against real fixtures for **all four leagues** (pro ids, OT, live-mixed, and an unmapped-team case): `tools/sim/run.sh` → `espnparse`
- **Pro id remap (parse boundary)**: the ESPN scoreboard ids are NOT the balldontlie ids every consumer speaks (logos, venues, NVS blobs — the namespaces overlap: ESPN 17 = BKN, balldontlie 17 = POR), so `finish_event` maps team ids through the generated `main/pro_team_ids.c/h` (`python3 tools/make_pro_id_map.py`, join = team **full name**, capped to the live namespaces NBA 30 / WNBA 13; full join rationale in the generator docstring). Unmapped → id 0 → the placeholder logo ring; **never** the raw ESPN id
- **Shared types**: `nba_api.h` survives as the **types-only** header (`nba_game_t` / `league_t`, NBA/WNBA/NCAAB/NCAAW) used by every screen, cache and blob; `nba_api.c` is gone (kept the header to avoid rename churn across the whole tree). `time_sync.c/h` sets the system clock from the HTTPS `Date` header (no SNTP) — one HEAD probe of ESPN's NBA scoreboard per boot, deliberately unpaced, and `time_sync_game_day_epoch()` (day 0 = `now - 12 h`) still anchors all day maths on the **US game day**, which is what ESPN's `date` strings are
- **Logo dispatch**: `league_logos.c/h` — `game_logo(league, id)` picks the right table (`team_logo` 1..30 / `wnba_team_logo` 1..13 / `ncaa_team_logo` ESPN school ids, shared by NCAAB+NCAAW). Never pick by the raw id number: all three namespaces overlap
- **Venues**: `team_venues.c/h` — **generated** (do not edit) home arenas for the 30 NBA + 13 WNBA teams, keyed per league by balldontlie id (same overlapping-namespace rule as the logos). balldontlie carries no arena data at all (games and `/teams` both lack it) and ESPN's pro `/teams` endpoint does too — but ESPN's pro **scoreboard** names every event's venue, so `tools/make_team_venues.py` harvests scoreboards day-by-day across season windows (cached `tools/logos/venues_harvest.json`, `--refresh` re-walks). Join key is the team FULL NAME: ESPN's pro abbrevs differ from balldontlie's, and balldontlie's `/teams` also lists retired franchises whose names collide with live ones (id 50 = the BAA Denver Nuggets) — the table is capped to the current namespace (30/13). College needs no table: the ESPN scoreboard carries `competitions[].venue` per game, parsed into `nba_game_t.venue` (exact even at neutral sites — the Big East final shows PeoplesBank Arena, not UConn's gym). Assembly rule: arena first, `", City ST"` appended only when the whole tail fits `venue[48]` — half a city is worse than none. Cards show a `*` after the home abbreviation (no arena text fits a 46px card)
- **Team logos**: `team_logos.c/h` — **generated** (do not edit) const RGB565A8 bitmaps, ~22 px, for the 30 NBA + 13 current WNBA + **conference-trimmed** NCAA D1 schools — 182 power-5/group-of-5-core by default (membership from one ESPN standings call, cached `ncaa_conferences.json`; `--all-conferences` bakes all 362), ~315 KB of bitmaps total. Teams outside the baked table get cards_screen's runtime placeholder ring. balldontlie NBA and WNBA ids are separate overlapping namespaces, and ESPN school ids are a third, so there is one accessor per league: `team_logo(id)` (1..30) / `wnba_team_logo(id)` (1..13) / `ncaa_team_logo(id)` (ESPN school ids, one set shared by NCAAB+NCAAW) — pick by the feed the game came from, never by the number; screens call them via `game_logo(league, id)` in `league_logos.c/h`. Regenerate with `python3 tools/make_team_logos.py [--league nba|wnba|ncaa|all]` (NBA: cdn.nba.com SVGs, ESPN fallback; WNBA: ESPN `wnba/500/<slug>.png`; NCAA: ESPN `ncaa/500/<espn_id>.png` + the school list from ESPN's leagues endpoint; team lists from balldontlie `/teams` endpoints, WNBA roster baked as fallback since that endpoint 404s intermittently). Emits a labelled `tools/logos/contact_sheet.png` — eyeball it, the CDN ids are not derivable from balldontlie ids (and ESPN school ids are not guessable either: UK=96, MSU=127, NKU=94). Pixels live in flash; only the `lv_image` widget costs LVGL pool (~600 B/card). Generator symbol tables are keyed per league with prefixed names (the NCAA abbreviations are not unique)
- **Score feed**: `nba_service.c/h` — resident FreeRTOS worker started at boot (`app_main.c`, unconditional — an unreachable saved AP still paints the NVS snapshot board = saved-data-only, and every network attempt falls into ordinary backoff; the `WIFI_STATE_CONNECTED` callback `nba_service_request_refresh()`-pokes it out of the sleep, so the first real cycle lands the instant any network arrives; the wolfSSL spike build keeps the old connect-gated start); keeps a newest-first cache of 4 pages of games (`SVC_PAGE_SIZE`, 3 by default — the adopted shape), walks ESPN **one day per request** backwards until the page fills or `SVC_EMPTY_CHUNKS` (2) consecutive empty days earn `s_older_exhausted`, then calls `cards_screen_show_games()` / `cards_screen_show_message()` inside `lvgl_port_lock()`. (The balldontlie machinery is gone: no cursor walk, no `season_type` memory, no adaptive chunk width, no 13 s quota pacing — ESPN's own 4 s pacing governs every request.) After a successful cycle it snapshots the newest page of the **pro** leagues to NVS (only when changed) and loads that snapshot at worker start / league switch, so boots render in ~8 s — and a boot inside the refresh interval skips the first fetch (`!poked` only; the blob path also sets `s_older_exhausted` — a snapshot knows nothing older than itself — so the walk re-earns the flag on the next real fill). A successful `svc_fill_recent` also drops cache games dated beyond `max(today, slate) + 1 day`: a shifted-clock soak build (`CYD_TEST_DAY_SHIFT`) can otherwise park a future day's games on the newest edge forever, since re-anchoring only walks backwards and `svc_persist` keeps re-saving them. `nba_service_set_league(lg)` (cards-screen tabs) is **queue-only** (it runs with the port mutex held, which is not recursive): it parks the target in `s_pending_league`, sets the flags and wakes the worker — the cache/pager wipe, "Loading..." and the new league's first fetch all happen on the worker at a cycle boundary, and every fetch/slate-hunt loop bails at its next request when a switch is pending (a half-built page is never rendered or persisted). Feed state (`s_league`, `s_cache`, …) is mutated **only by the worker**; mutating it from the tab callback is what once let an in-flight cycle merge the old league's games into the wiped cache (mixed boards under the new tab — see Lessons). The tab highlight follows the tapped label explicitly. Refresh every `NBA_SERVICE_REFRESH_MS` (override: `idf.py -DCYD_NBA_REFRESH_S=45 build`): on page 1 it re-anchors on today (picks up starting games and new slates), deeper pages are refetched only by the header button or when they hold unfinished games. Any **dead league** (college in October, the WNBA after its finals) gets an empty newest-edge fill answered by a forward hunt for the nearest upcoming slate (`svc_find_nearest_slate`: week-jump + bracket walk-back, ~9 requests, remembered per league in `s_slate_day[]` — kept across tab switches so the pre-warm's probe is reusable), and the pager anchors there so scheduled games + tip text show instead of "No data". A **clean-empty hunt** (every probe answered, all empty) is remembered too in `s_slate_none_at[]`: the dead league re-probes weekly, not every 15-minute cycle — a probe that *errored* is never treated as a verdict of empty. The worker **pre-warms every hidden tab** on the first *connected* successful cycle (`svc_prewarm_tabs` — the once-per-boot slot is consumed only with Wi-Fi up, so an offline boot's blob-render cannot burn it; a league whose box is inside the 6 h freshness rule logs `box still recent - skipped`; ~10 polite background requests — all four leagues ride ESPN, so quota fear is gone; sparse slate days top the box up from the probed window). Tab switches paint via **per-league page boxes** (`s_page_box[4]`, RAM, up to `SVC_BOX_GAMES` = 4 pages = 12 games per tab): every successful cycle parks the shown league's newest games in its tab's box (`svc_persist` → `svc_box_store`), switching away stashes the leaving board's page one more time, and the pre-warm fills the three boxes nobody has visited yet. `svc_cache_load` (run at worker start and at every switch) tries the box first for *any* league, then the NVS blob (pro leagues only — covers reboots), and ends in an early `svc_render` whenever it hits, before the refill runs. A box restore also snaps the pager to **where the viewer left that tab** (`s_last_page[lg]`, saved every successful cycle, clamped to the box's page count). So a tab that has been shown once in the session is instant forever after (measured ~200 ms box paint on device), and first-ever visits are warm too — the pre-warm covers all three hidden tabs. Boxes are RAM rather than NVS: a 3rd/4th ~4.4 KB blob would eat the 24 KB partition's GC headroom, and "instant switch" is session-scoped. `nba_service_request_refresh()` and `nba_service_step_page(delta)` (pager arrows) both give the wake binary semaphore. `svc_render()` skips pushing a page into a **hidden** screen (`cards_screen_page_visible()`) — the detail view needs that LVGL pool — and `nba_service_rerender()` rebuilds the page from cache when the board comes back (no HTTP; note `cards_loaded_cb` only pokes when the container is **empty** — the create-time "No games to display" seed means no poke fires at boot, by design). **Idle prefetch**: after a successful, unpoked cycle the worker walks up to `SVC_IDLE_PREFETCH_DAYS` (3) more days into the cache's free slots so the next `<` renders from RAM, aborting the moment a tap or switch lands. A page step that lands past the edge of history (`ESP_ERR_NOT_FOUND`) renders the nearest cached page and must **not** join `s_fail_streak`/the backoff — reaching the edge is an answer, not a network failure (see Lessons)
- **NVS**: `nvs_settings.c/h` — calibration data + saved flag persistence with validation (range 0-4095), brightness, and generic sized-blob helpers used by the score feed's cross-reboot cache (`games_nba` / `games_wnba`, 12 games ~4.4 KB each; college not persisted — a 3rd/4th blob would eat the 24 KB partition's GC headroom, and the college tabs' RAM page boxes already cover the in-session case). Blob header carries a `SVC_BLOB_MAGIC` version + `sizeof(nba_game_t)` so a struct change — or a magic bump (done when the ghost filter landed, to purge snapshots that still hold `canceled` rows) — self-rejects old snapshots; balldontlie-era snapshots stayed valid across the ESPN migration on purpose (same struct, same id namespace — the remap happens before the blob), and device-verified as accepted
- **UI constants**: `ui_common.h` — shared dimensions (header heights, row widths, keyboard height…) and color palette macros for all screens; no magic numbers in screen files
- **Busy indicator**: the pager strip carries an `lv_spinner` (`CONFIG_LV_USE_SPINNER`, white 200° comet = LVGL default sweep, ~750 B pool) that the feed worker spins via `cards_screen_set_busy()` — `svc_busy()` wraps every blocking network call in the cycle branch chain (page walk, fill, refetch) in on/off, under the port lock like all worker→LVGL calls. Hidden otherwise (a hidden LVGL object costs no draw time). It answers "is the board hung or loading?" during the ESPN-paced day walks where a page step or cold-league fill takes tens of seconds (one polite request per day)
- **Hardware**: `hardware.h` (all pin defines, LCD/touch/LEDC constants), `lcd.c/h` (SPI init + backlight PWM)
- **Touch**: `touch_integration.c` — XPT2046 on SPI3 (`esp_lcd_touch_new_spi_xpt2046`), indev via `lvgl_port_add_touch`; the raw-ADC→screen linear map lives in the `process_coordinates` callback (4-point calibration min/max + the calibration data's `swap_xy`). Driver rotation flags stay **false on purpose** — the base driver applies them *after* the callback, so a driver-side swap/mirror would flip already-calibrated screen coords (per-panel orientation variance is what the calibration data absorbs). `CONFIG_XPT2046_INTERRUPT_MODE=y` (sdkconfig.defaults, 2026-10): every read is gated on the PENIRQ pin (GPIO36, active low) — idle polls are a GPIO read with no SPI, and a ghost reading needs physical pen contact to reach the Z check; `CONFIG_XPT2046_Z_THRESHOLD` (default 400) is the knob if ghosts ever appear

## Navigation Pattern

Every screen has a `*_screen_create(void)` factory. Navigation uses setter functions + static callbacks:

```c
// In app_main.c, after creating screens:
cards_screen_set_settings_scr(settings_scr);
settings_screen_set_wifi_scr(wifi_scr);
settings_screen_set_cards_scr(cards_scr);
wifi_screen_set_settings_scr(settings_scr);

// In a screen .c, static callback:
static void nav_to_settings(lv_event_t *e) {
    lv_obj_t *target = (lv_obj_t *)lv_event_get_user_data(e);
    lv_scr_load(target);
}
// OR using setter + NULL user_data (see cards_screen.c settings_btn_event_cb)
```

**Adding a new navigation link**: create setter in target screen header, call it from `app_main.c`, add static callback in source screen.

## Constraints

- **C only** — no lambdas, no C++. All callbacks are `static void fn(lv_event_t *e)`.
- **ESP32** (not ESP32-S3) — different SIMD optimizations, different GPIO.
- **Display rotation**: `swap_xy=true, mirror_x=true, mirror_y=false` (in `lcd.c` and `touch_integration.c`).
- **Touch rotation**: the driver's `swap_xy`/`mirror_x`/`mirror_y` stay **all false** (`touch_integration.c` `touch_cfg`) — `esp_lcd_touch` applies those flags *after* the `process_coordinates` callback, so enabling them mirrors/swaps the already-calibrated SCREEN coords and breaks orientation. The panel's axis swap is handled by the calibration data's `swap_xy` flag inside the callback (and per-panel quirks by the 4-point min/max map — a different panel needs recalibration, not flag changes; the AGENTS line claiming `swap_xy=true` in the driver was stale, corrected 2026-10).
- **Flash**: 4MB, BOYA chip, single app partition (`sdkconfig.defaults`). The binary is ~1.74MB / 2MB partition (**~17% free**) after the NCAA conference trim (was 4% with all 362 schools) — flash is still the scarce resource; measure `check_sizes.py` output before baking more art or tables.
- **Backlight**: LEDC PWM on GPIO 21, 5kHz. `lcd_brightness_set(duty)` sets LEDC duty directly.
- **LVGL fonts**: Montserrat 12, 14, 16, 20 linked (14 is `LV_FONT_DEFAULT` — the keyboard paints its keys with it). 48 is enabled in sdkconfig but unreferenced, so the linker GCs it; if a future screen uses it, flash costs ~17 KB.
- **Perf build**: `sdkconfig.defaults` sets `CONFIG_COMPILER_OPTIMIZATION_PERF` (-O2) and 240MHz CPU. LCD SPI runs at 40MHz (`LCD_PIXEL_CLOCK_HZ` in `hardware.h`, already max reliable on this board's wiring). Do NOT enable `CONFIG_LV_ATTRIBUTE_FAST_MEM_USE_IRAM` — LVGL 9.5's `LV_ATTRIBUTE_FAST_MEM` declarations collide and fail `-Werror`. `-O2` surfaces `-Wstringop-truncation`/`-Wformat-truncation` in esp_wifi ssid/password `strncpy` copies: use `strnlen` + `memcpy` into the zero-initialized `wifi_config_t` fields.
- **Color palette**: bg `0x16213e`, header `0x0f3460`, text `0xffffff`, subtle `0x555555`.

## Touch Integration (Complete)

Current state: touch hardware init works, LVGL indev registered, calibration screen wired into boot flow.
- Boot flow: NVS check → if no valid calibration, load calibration screen; if valid, splash → cards
- Calibration: 4-corner crosshair, quadrant validation, 500ms debounce, long-press undo
- Back navigation: calibration_screen_set_back_scr(settings_scr) for returning from settings
- Reset: calibration_screen_reset() called before loading calibration from settings

## Pro Team Id Map

`main/pro_team_ids.c` is generated — regenerate (never hand-edit) with:

```bash
python3 tools/make_pro_id_map.py
```

It bakes ESPN scoreboard team ids → balldontlie ids (the namespace every
consumer speaks: logos, venues, NVS blobs) for NBA 30 + WNBA 13, joined by
team **full name** and capped to the live namespaces. Teams without a mapping
read id 0 and draw the placeholder ring (deliberate: Portland Fire and the
Toronto Tempo have no baked logo yet). Caches the ESPN team lists at
`tools/logos/espn_teams_{nba,wnba}.json`.

## UI Preview (host, no hardware)

```bash
tools/sim/run.sh    # -> /tmp/opencode/cards_screen.png (320x240)
```

Compiles the real screen `.c` files against host LVGL (`lv_conf.h` in `tools/sim/`, fonts matched to `sdkconfig`), renders into an RGB565 framebuffer and dumps a PNG. ESP-IDF headers are stubbed in `tools/sim/shim/` and device-only symbols in `tools/sim/stubs.c`. To preview a new screen: add its `.c` to `add_executable` in `tools/sim/CMakeLists.txt`, call its `*_screen_create()` from `tools/sim/main.c`, and add stubs for whatever it links against.

## Lessons Learned

- **ESPN event stamps are UTC; the scoreboard's "day" is a US game day**: copying the `YYYY-MM-DD` prefix of `events[].date` dated evening US games as TOMORROW (device bug 2026-10: tonight's Nuggets@OKC listed on the 23rd — the UTC stamp is `2026-10-23T02:30Z`). The parser stamps game day = stamp − 12 h instead (the `time_sync_game_day_epoch` convention, and the day ESPN's `dates=` query is keyed on), and the fixture test in `tools/sim` asserts it for every parsed game against glibc `timegm`. The fix itself nearly shipped a second bug: a digit-clamp written `y & 9999` is a **bitwise AND**, not modulo (2026 → 1802) — caught seconds later by that same new assertion. Blob `SVC_BLOB_MAGIC` was bumped alongside (stored snapshots carried the UTC-dated games).
- **LVGL timer**: `lv_timer_create()` creates an infinite-repeat timer by default (`repeat_cnt=0`). Use `lv_timer_set_repeat_count(timer, 1)` for one-shot timers. The `lv_timer_t` struct is opaque — don't access members directly.
- **NVS validation**: Always validate calibration data ranges (0-4095 for XPT2046) before trusting the `cal_saved` flag. Corrupt NVS data can cause inverted touch mapping, making buttons auto-fire on wrong screens.
- **Flash and NVS**: Using `esptool merge-bin` may not erase the NVS partition. If calibration data is corrupt, run `idf.py erase-flash` before flashing, or rely on the built-in validation that resets corrupt data to defaults.
- **Backlight polarity**: CYD2USB backlight is **active-low** (GPIO LOW = ON). `lcd_brightness_set(brightness)` must invert: `duty = LEDC_DUTY_MAX - brightness`. Without inversion, higher brightness values make the screen darker.
- **LVGL screen padding**: the default theme gives screens/containers `card` style `pad_all ≈ 13px`. It shrinks `LV_PCT(100)` sizes and offsets `set_pos`/`align` (e.g. keyboard `BOTTOM_MID` floats 13px up). Always `lv_obj_set_style_pad_all(scr, 0, 0)` on every screen. Same trap on **small fixed-height row containers** (e.g. 22px list rows): padding exceeds the height → negative content box → flex centering pushes children *outside* the row (they render over neighbouring widgets). Zero `pad_all` on every `lv_obj_create` you use as a row.
- **LVGL flex centering**: `lv_obj_set_flex_align(obj, main, cross, track)` — the 3rd arg places the *track* (a column track is as wide as its widest child). `CENTER` for cross alone is not enough: the track itself stays at the left edge. Use `LV_FLEX_ALIGN_CENTER` for both cross and track.
- **`LV_PCT(100) - N` is a trap**: it subtracts N from the fixed-point percent, not pixels (`LV_PCT(100)-40` = 234px, not 200). Use `LV_VER_RES - N` instead.
- **esp_lvgl_port thread safety**: the LVGL port task renders continuously and holds a mutex. **Any** LVGL call from another task (creating screens in `app_main`, `lv_timer_create/del` or widget updates from `esp_event`/backend task callbacks) must be wrapped in `lvgl_port_lock(0)`/`lvgl_port_unlock()`. Unserialized access causes intermittent `LoadProhibited` panics deep inside LVGL (observed in `lv_event_send` during screen creation — timing-dependent, may not crash for many boots). The port mutex is **not recursive**: never take it from LVGL task context (timer/event callbacks already run with it held).
- **Scroll room for the keyboard**: a scrollable container's `pad_bottom` extends its scroll range (via `lv_obj_get_self_height`). The wifi screen sets `pad_bottom = UI_KEYBOARD_H` on the content column so any focused field can scroll fully above the keyboard (`textarea_focus_cb` computes the minimal scroll).
- **ESP-IDF 6 http client**: event handler signature is `esp_err_t fn(esp_http_client_event_t *evt)` — no separate `client` arg (it's `evt->client`, and `evt->user_data` comes from `config.user_data`). `esp_http_client_get_last_errno()` was renamed `esp_http_client_get_errno()`. `esp_crt_bundle_attach` needs `#include "esp_crt_bundle.h"`.
- **HTTPS cert chains ending at a cross-signed root** (e.g. balldontlie.io's GTS cert served under a GlobalSign cross-cert) fail with `-0x3000` unless `CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_CROSS_SIGNED_VERIFY=y` (set in `sdkconfig.defaults`).
- **esp_http_client treats 4xx as errors** (`perform()` returns non-OK) — but headers/status/body are still delivered. For probes where the response *content* is what matters (e.g. the `Date` header in `time_sync.c`), check `get_status_code()`/captured headers instead of `perform()`'s return code.
- *(historical — cJSON dropped with balldontlie; the static-slot rule stays)* **cJSON memory budget on this board**: the cJSON tree costs ~3-4x the JSON text size. A full balldontlie page at `NBA_API_PER_PAGE`=12 is ~10.7 KB → ~42 KB tree; parse-time free heap sits at ~46-52 KB depending on fragmentation. `per_page=15` (13.3 KB → ~46.5 KB tree) OOM'd mid-parse once the venue field grew `nba_game_t` — +48 B lands on ~79 static game slots (cache, page boxes, API page), and statics come out of the same internal-RAM pool as the heap. The ESPN streaming parser erased the tree cliff entirely (constant memory at any body size), but the static-slot cost is still live — the 16-game page boxes took `.bss` +11.7 KB and boot heap came down ~11.7 KB with them. Parse-failure diagnostics of the tree era: `cJSON_GetErrorPtr()` offset into the body reveals truncation-vs-OOM (failing deep inside a valid 13285-byte body = OOM, not truncation).
- *(historical — balldontlie, retired 2026-10)* **balldontlie date queries**: `start_date`/`end_date` are inclusive; `season_type` omitted means *all non-preseason types* (October queries return 0 games until the `preseason` fallback runs). Each game carries quarter-by-quarter stats (~880B/game) — that's why `per_page` stays small.
- *(historical — balldontlie, retired 2026-10)* **balldontlie pages by game id, not by date, and ignores `sort`/`order`**: `next_cursor` means "games with a bigger id", and ids do not track game dates (a game added late to the schedule, e.g. a reschedule, gets a big id — Oct 14 2026 had id 22093897 while Oct 16 games were 2182619x). So a cursor page is never "the newest games", and a *partial* cursor walk leaves holes you can never fill. `nba_service` therefore fetched whole date chunks following `next_cursor` and sorted by `datetime` (ISO 8601 UTC — the string compares chronologically) newest-first — the day-walk the ESPN client uses now sidesteps the cursor entirely.
- *(quota historical — balldontlie retired; the `s_fail_streak`/backoff rules it shaped are live)* **The free balldontlie tier allows ~5 requests per minute**, and a chunk fetch costs 1-3 HTTPS calls (cursor pages + the preseason fallback on an empty chunk). `nba_api` therefore paces itself (`NBA_API_MIN_GAP_MS`, 13 s; `nba_api_note_request()` lets the clock-sync probe count too) and `nba_service` adapts the chunk width to cost-per-request (`svc_note_chunk_yield`). Any retry path must also be gated: an early version clamped a failed page back and re-requested it every cycle, which hammered the API (37 × 429) and, worse, reset the cache on the way, blanking a board that still had good data. Now: `s_fail_streak` drives a 15 s → 5 min backoff, a failed page move renders the nearest *cached* page, and re-anchoring on recent games only rewrites the cache after a successful fetch.
- **balldontlie dates are US game dates (ESPN's `date` strings too), the ESP32 clock is UTC**: games tip off in the US evening, which is already the next UTC day, so `time(NULL)`-based day maths labels tonight's games a day early. `time_sync_game_day_epoch()` anchors day 0 at `now - 12h` so the pager's "today" matches what the feed reports.
- **Recolouring a button does not reach its child label** if the label got its own `lv_obj_set_style_text_color()`: child styles win over inherited ones. To dim a disabled `◀`/`▶`, set the colour on the *button* and leave the label unstyled (`cards_screen.c: make_page_button`).
- **HTTPS connections creep the heap (~200 B each)**: measured over 8 refresh cycles with the sample taken a full interval *after* the connection closed (so lwIP's deferred teardown is not blamed), free heap fell 98008 → 96808. Our own allocations balance; the loss is inside `esp_http_client`/esp-tls. Disabling `CONFIG_MBEDTLS_CLIENT_SSL_SESSION_TICKETS` did **not** help. Open as few connections as the feed design allows (burst keep-alive lands this at ~1 connection per refresh cycle) and let `nba_service` reboot below `SVC_MIN_FREE_HEAP` (25 KB) — with the creep that is roughly one self-healing reboot per week. Two floors stand between the drift and the TLS failure band (~45.5 K free heap with the forced 16 KB IN buffers; storm floor restart at 46 KB after 3 straight fetch failures, pre-warm gate at 48 KB — see the cert-storm lesson below for why 46). With the mbedTLS arena ON by default both storm-specific floors are gated on `mbedtls_arena_active()` (they read as failures at the arena shape's permanently-lower pool — see the allocator-floor lesson); the 25 KB absolute floor stays load-bearing everywhere, because the drift lives in lwIP, not in the TLS allocator.
- **Host UI preview (`tools/sim/`) gotchas**: (a) `lv_conf_template.h` wraps its whole body in `#if 0` — the copied `tools/sim/lv_conf.h` must flip it to `#if 1`, otherwise every define is ignored and LVGL silently compiles with defaults (missing fonts). (b) `LV_HOR_RES`/`LV_VER_RES` are **runtime** macros (`lv_display_get_horizontal_resolution(lv_display_get_default())`); using them in `lv_display_create()` before a display exists gives a 0x0 display and an endless refresh loop — use literal 320/240 in the harness. (c) `lv_conf_internal.h` prints `#pragma message("Possible failure to include lv_conf.h")` when the config isn't picked up.
- **LVGL built-in fonts are ASCII + `LV_SYMBOL_*` only**: typographic characters (em dash `—`, curly quotes) render as empty boxes. Keep on-screen strings to ASCII.
- **Absolute placement inside a flex container**: add `LV_OBJ_FLAG_FLOATING` to the child (the date/status labels on a score card) — otherwise it joins the layout and shifts its siblings.
- **Watch macro parameter names against struct members**: `#define G(date, ...)` used in `{ .date = date }` rewrites the *member name* too (`.​"2026-10-14" = ...`). Prefix parameters (`d`, `stat`, `tm`).
- **Header row needs `pad_all = 0` too**: the theme's ~13px padding on the 320px header eats 26px, and a `flex_grow(1)` status label then wraps to two lines mid-word.
- **`xQueueReceive(q, NULL, timeout)` asserts** (`queue.c: (!(pvBuffer == NULL && pxQueue->uxItemSize != 0))`) when the queue holds non-zero-size items — it took down the score-feed worker in a reboot loop. For "wake me up" signalling use a binary semaphore (`xSemaphoreCreateBinary` + `xSemaphoreGive`/`xSemaphoreTake` with the timeout), not a 1-byte queue.
- **Render memory**: LVGL widgets are allocated from LVGL's own pool (`CONFIG_LV_MEM_SIZE_KILOBYTES=64`), so `esp_get_free_heap_size()` looks unchanged after building 15 cards. Log `lv_mem_monitor()` (`used_pct`/`frag_pct`) alongside it to see real render headroom.
- **`LV_LABEL_LONG_DOT` needs a bounded height**: on a label with `LV_SIZE_CONTENT` height the text *wraps and grows* instead of truncating. Single-line cells (the box-score table's team names) get an explicit height (~18px for 12pt) to get the `…` clip.
- **Never delete a widget from its own event callback**: the card tap that opens the detail view cannot `lv_obj_clean()` the container holding the card LVGL is still sending the event to. Copy the payload into a static, then defer one tick with a one-shot `lv_timer_create(cb, 5, NULL)` + `lv_timer_set_repeat_count(t, 1)` (LVGL frees a finished one-shot by itself).
- **Freeing a whole screen from a button on that screen**: `lv_scr_load(other)` first, then `lv_obj_delete_async(old_scr)` (LVGL 9, `lv_obj_tree.h`) — the delete runs on the next timer pass, out of the event. The detail view tears itself down this way on the back tap; keeping it alive instead cost 14 points of LVGL pool in the steady state (71% vs 57%). Remember to NULL the cached widget pointers.
- **`LV_EVENT_SCREEN_LOADED` is sent to the screen object** (`lv_obj_send_event(scr, …)`), so a screen can react to being shown: the cards screen asks `nba_service_rerender()` for its page back whenever it loads with an empty container. Pair it with `cards_screen_page_visible()` so the feed never builds a page of cards inside a hidden screen.
- **`snprintf`ing API struct fields needs explicit precision** (`"%.8s @ %.8s"`, `cell[16]` for `%d`): `-Werror=format-truncation` under `-O2` treats `char abbr[8]` + `%s` as unbounded and refuses the build. And when the warning lands on a line you did **not** touch: an edit elsewhere in the caller changed gcc's inlining/range analysis, and the previously-unchecked snprintf is now measured — bound the width there too (`%d%s%.11s` for the period+clock status string; live clock text never nears it).
- **balldontlie `team_id` is NOT `cdn.nba.com_id - 1610612736`**: only ATL/BOS line up; e.g. balldontlie 3 = BKN but 1610612739 = CLE (BKN's NBA.com id is 1610612751). `tools/make_team_logos.py` keeps an explicit abbr→CDN-id table and emits a labelled contact sheet — check it by eye instead of trusting any arithmetic.
- **Hand-packed LVGL images**: RGB565A8 = RGB565 plane (little-endian, `stride = w*2`) immediately followed by the A8 mask (`w*h` bytes), descriptor `.cf = LV_COLOR_FORMAT_RGB565A8, .data_size = color + alpha`. `tools/make_team_logos.py` implements the packing; validate against LVGL's `_calculate_draw_buf_size` before rendering blind.
- **Never pass an out-param and read it in the same call**: `lookup(table(&n), n, id)` is legal C but the arg evaluation order is unspecified — gcc/x86 read the garbage `n` *before* filling it (every logo silently vanished in the sim), xtensa happened to work. Sequence the calls in separate statements. Found by watching LVGL pool drop exactly one-card-per-image-worth in `tools/sim/` output — always diff the pool numbers after touching render-path code.
- *(historical — balldontlie WNBA retired 2026-10; ESPN serves WNBA like any other league, per-period stats included)* **balldontlie WNBA payload differs from NBA**: no `datetime` (`date` holds the full ISO UTC stamp — split it), scores are top-level `away_score`/`home_score`, `status` is `pre`/`in`/`post` with the readable word in `status_state`, and there are **no per-period stats** (detail view hides the box-score table when every `q[]` is -1 — the rule itself still guards any payload without periods). The `season_type`/preseason fallback is NBA-only — and a struct-literal mock that omits the `q[]` arrays zero-inits them and fakes a table: set them to -1 explicitly.
- **LVGL floating labels align against the *padding* box**: when the card's flex row is pinned by `pad_top`/`pad_bottom` (46px cards), `lv_obj_align(..., BOTTOM_*, ...)` on the card's FLOATING children lands *inside the row band* (names over the score). Pin those children with explicit y offsets from `TOP_*` edges (`UI_CARD_NAME_ROW_Y`).
- **balldontlie/UA quirks (PC-side)**: the balldontlie edge 404s `/wnba/*` for unknown User-Agents (browser UA works, and the WNBA `teams` endpoint is intermittently flaky even so — generator carries a baked roster fallback); ESPN's CDN image endpoints 404 on Python's default `Python-urllib` UA. Both only matter for `tools/make_team_logos.py`, the ESP32 client is unaffected. (The ESPN *scoreboard* API wants a browser `User-Agent` too — `espn_api.c` sends `Mozilla/5.0`.)
- **Hand-written JSON scanners: clear "last token was a value" flags when a container opens**. A `':'` sets "next token is a value"; `"events":` then `[`/`{` never delivers that scalar, so the flag leaked and the *first key* of every object was consumed as a value — all later assignments keyed off the seeded container name. Symptom: near-total data loss with a few fields (second keys) surviving, which looks like depth-tracking bugs. `open_container` must reset the flag. And **test the parser on the host against real captured payloads first** (`tools/sim/run.sh` → `espnparse`): the same fixture run caught this plus two ESPN-shape traps below before a single byte was flashed.
- **ESPN scoreboard pre-seeds games it hasn't played**: `"score":"0"`, `"period":0`, a `"0:00"` displayClock and `"TBD"` shortDetail on scheduled events. Unless the parser forces score/linescores to -1 outside `in`/`final` (and prefers the tip text over the zeroed clock), the board shows "0 - 0" for tomorrow's games. Also: ESPN lists a 69-game November slate **oldest-tip-first**, so capping at N games by append order keeps the *wrong* half — keep the newest N via capped sorted insertion.
- **CMake `if(NOT X STREQUAL "")` is TRUE for an *undefined* X** (the bare name compares as its own literal), so the guard emitted `-DCYD_TEST_DAY_SHIFT=()` for plain builds. Test-hook guards must be `if(DEFINED X AND NOT X STREQUAL "")`. Related: **idf.py keeps `-D` options in the CMake cache** — after a `-DCYD_TEST_LEAGUE=2` soak, the next plain `idf.py build` still flashes the hooks; clear them with the empty form `idf.py -DCYD_TEST_LEAGUE= -DCYD_TEST_DAY_SHIFT= build`.
- **Header widgets eat LVGL pool faster than expected**: an `lv_btn` is two widgets (button + child label), and *each* `lv_obj_set_style_*` call allocates a per-object style property. 3 button-tabs were ~5 pool points and pushed the 12-card stress board past 100% (render hang at 99%, no crash line). The tabs are now clickable **labels** sharing one static `lv_style_t` (~2 points, 8-card board back at ~70%). Gotcha: `lv_style_set_*` has **no state selector** — pressed/hover colors go on `lv_obj_add_style(obj, &style, LV_STATE_PRESSED)` or a local property; and local properties outrank added styles, so an active-tab local bg also beats a shared PRESSED bg (no pressed flash).
- **A `-Wstringop-truncation` wrapper is still a wrapper**: even a `copy_str()` helper ending in `strncpy(dst,src,n-1); dst[n-1]=0;` gets flagged from `-O2 -Werror` when the source array is longer than the dest. Implement the helper with `strnlen(dst_len-1)` + `memcpy` + explicit NUL — deliberate truncation gcc cannot misread.
- **`pad_all = 0` does NOT zero `pad_column`**: the theme's 8px flex column gap survives it, and in the 320px header 7 gaps ate 56px (the Wi-Fi badge label got 26px and clipped to "Off"; the pager arrows floated off their labels' own padding). Zero `pad_column` explicitly on every flex row, and verify with the sim geometry dump (`lv_obj_get_style_pad_column()`) instead of squinting at the PNG.
- **Measure font widths, don't estimate them**: "WNBA" at Montserrat 12 is 41px (the `W` alone is ~14px) — `UI_TAB_W` must be 42 or the label wraps to two lines inside its fixed box. `lv_text_get_size()` in a sim debug print beats any eyeball check. The rename to `NCAA`/`NCAAW` proved the flip side: a **uniform** box sized for the widest label ("NCAAW" ~49px) overflowed the header and pushed the gear off-screen — tabs are now sized per label (`lv_text_get_size` + `UI_TAB_PADX`), and `SIM_HEADER_DUMP=1 ./build/cyd_sim ncaa` prints every header child's x/w so the fit is measured, not squinted at.
- **Missing LVGL symbols get composed, not drawn**: LVGL has `LV_SYMBOL_WIFI` but no slashed "Wi-Fi off" variant — the badge overlays an `LV_SYMBOL_CLOSE` child label **painted in the header background colour** (a black X on a black fan is invisible; the header colour only shows where the X bites the fan), and blinks a greyed fan while connecting with one `lv_timer` toggling `text_opa` (two flips/s, zero allocations — blinking is NOT expensive). Child labels ride the parent's flex slot; `lv_obj_align` lands on the parent's PADDING box, so compensate the parent's `pad_left`. Keep the **grow label** visible-but-empty whenever a mark is up — its `flex_grow(1)` pins the header buttons in every state. (Same underlying rule as the U+1C64 detour: built-in fonts are ASCII + `LV_SYMBOL_*` only — when a needed glyph is missing, compose it from symbols or bake a bitmap; the native-glyph composition won, no flash cost.)
- **A smaller-than-a-page slate can park cached games out of sight**: `page_slice()` refuses a short page 0 unless `s_older_exhausted` is set — a 2-game ESPN slate filled the cache while the board showed "No games". The empty-chunk policy (`SVC_EMPTY_CHUNKS`) must be tallied in the *fill* walk, not only in page-stepping; and re-anchoring resets the flag, so the walk must re-earn it every cycle.
- **League-derived state set only in the setter goes stale on hook boots**: the college 1-day chunk clamp lived in `nba_service_set_league()`, but `-DCYD_TEST_LEAGUE=2` seeds the league statically — every chunk cost 2 ESPN requests (`s_chunk_days`'s static init is 2). Clamp league-dependent state at the use site too.
- **A shared API client must not be the only place a record's owner is known**: `nba_api.parse_game` memsets `nba_game_t` and never touches `.league`, so every balldontlie game landed as `LEAGUE_NBA` (0) — WNBA cards dispatched through the *NBA* logo table (the id namespaces overlap!) and the per-game league check on the NVS blob correctly rejected every legitimate WNBA snapshot. The balldontlie parse can't stamp it (it doesn't know which endpoint it parsed), so `svc_fetch_range_season` stamps `s_league` onto every fetched game before merging — single call site, both leagues. Found because the blob validation refused data it should have accepted; the check that surfaced it is the reason to keep it.
- **A cross-task flag setter must not mutate the *data* the other task owns**: the league tab callback called `nba_service_set_league()`, which wiped `s_cache_count` and flipped `s_league` while the feed worker was mid-fetch (a balldontlie chunk walk + the new boot pre-warm make that window 40-90 s). The in-flight cycle kept re-reading `s_league` per request and merging into the "empty" cache → the old league's games rendered under the new tab, and `svc_persist` could even save them under the new league's NVS key. Rule: a setter crossing tasks may touch *flags* only (pending-value + wake); the owning task applies them at a boundary, long loops check an abort flag per iteration, and the producing cycle skips render+persist when aborted. Belt-and-suspenders here: the blob loader rejects games whose `league` field mismatches the feed, self-healing snapshots written by the buggy build. Reproduce with `-DCYD_NBA_AUTOTAB=2` (timer-driven switch mid-first-fill).
- **Boot-time LVGL calls need the port lock too**: `lv_theme_default_init()` and `lvgl_port_add_touch()` in `app_main` ran unlocked while the port task had been rendering since `lcd_init()` — a race that survives for months, then goes *deterministic* on an unrelated binary-layout shift (WDT barking every 5 s, boot parked in `lv_inv_area` under `report_style_change`, no screen, decoded via `xtensa-esp32-elf-addr2line -pfiaC -e build/*.elf <addrs>`). Anything touching LVGL after `esp_lvgl_port_init()` — including app_main's pre-screen calls — must hold `lvgl_port_lock(0)`.
- **Never join two feeds on an abbreviation, and cap cross-feed tables at the live namespace**: mapping ESPN arenas onto balldontlie ids by `abbreviation` breaks (ESPN's pro abbrevs differ: NY vs NYK, WSH vs WAS); by `full_name` it works ("Atlanta Hawks" is unambiguous *within the current teams*). But balldontlie's `/teams` lists every franchise it ever had — the BAA Denver Nuggets (#50, "DN") shares the live Nuggets' full name, and Euro/international rows run to id 216597. An uncapped generated table indexed to the roster's max id silently baked ~850 KB of NULL pointers. Rule: harvest only what the *current* scoreboard can name, size the table to the documented namespace (30/13), and warn on holes inside that cap.
- **A capture script still alive on /dev/ttyUSB0 looks exactly like a dead board**: the next reader gets `SerialException: device reports readiness to read but returned no data (device disconnected or multiple access on port?)` while the board happily keeps running — and the capture's own log file lags reality by its write buffer, so the last line is where the reader *stopped seeing data*, not where the board stopped logging. Check `fuser /dev/ttyUSB0` before believing a hang; wait for (or kill) the holder, then read the finished file.
- **Do NOT shrink `CONFIG_MBEDTLS_SSL_IN_CONTENT_LEN`**: 4096 broke every ESPN handshake deterministically (`mbedtls_ssl_handshake returned -0x0087` = BUFFER_TOO_SMALL). ESP-IDF's mbedTLS port does not negotiate MaxFragmentLength, so the IN buffer must absorb whatever record size the server chooses — and CDN cert-chain records exceed 4 KB. `SSL_OUT_CONTENT_LEN=4096` is safe (we send tiny requests) and is the setting we keep; the ~12 KB/connection saving on the IN side is simply not purchasable this way. Commented in `sdkconfig.defaults`.
- **A backoff `xSemaphoreTake` must `continue` the loop on BOTH outcomes**: the wake branch continued but the *timeout* branch fell through into the bottom refresh-interval take — so a failed cycle slept the full 15 minutes whenever nothing poked the worker, and the log promising "waiting 15 s before retrying" lied. Soaks masked it because a poke always landed; the all-ESPN migration's first failed boot exposed it. The failure path now ends in an unconditional `continue` (all soak hooks are gated on success, so nothing else is skipped).
- **Reaching the edge of history is not a network failure**: a page step onto the exhausted edge (`svc_reach_page` → `ESP_ERR_NOT_FOUND`) rendered the nearest cached page correctly but then joined `s_fail_streak` → 15/30/60 s backoffs — a board that answered exactly as asked got treated like a dead network. The edge verdict now clears `err` (the `s_older_exhausted` flag short-circuits the next attempt before any HTTP, so there is no request loop); only real fetch errors drive the backoff. (Related soak artifact: AUTOPAGE steps `+1` from the *clamped* page, so it spins render-only cycles at the edge — harmless, zero HTTP, but read the log with that in mind.)
- **A slate hunt needs a memory of failure, not just of success**: a finished league (WNBA after the finals) has zero slates within +28 days, and without a verdict the hunt re-probed the same four empty days every 15-minute cycle (~20 req/hour on a dead feed). `s_slate_none_at[lg]` keeps a *clean-empty* verdict for a week — and a probe that ERRORED must never count as empty (a network blip would otherwise suppress retries for a week), so `slate_day_has_games` returns 1/0/-1, not a bool.
- **The "cert storm" was ESP-side memory, not the CDN — the log line lies**: clusters of `esp-x509-crt-bundle: PSA signature verification failed (-141)` looked like a broken edge cert; `-141` is actually `PSA_ERROR_INSUFFICIENT_MEMORY` (mbedTLS 4.1 codes; `-149` would be a real bad signature), and `esp_crt_bundle.c` never checks `psa_hash_compute()`'s return, so an allocator failure is printed as a crypto verdict. Reproduced on demand with `-DCYD_NBA_TLSSTRESS` (alternating ESPN/Google HEAD handshakes): handshakes pass down to ~45.5 K free heap (16 KB IN buffers), ESPN's RSA-2048 chain fails first (its verify scratch is heavier than Google's ECDSA), below ~41 K every host fails and **nothing self-heals** — only a reboot clears it. The board's post-pre-warm baseline sat 1-2 K above that line and esp-tls's ~200 B/connection creep crossed it about daily. Fixed as a package: burst keep-alive (A), the storm-floor restart (B), and the pre-warm heap gate (C). (`SSL_IN_CONTENT_LEN=8192` (D) looked validated on a HEAD-probe soak and then FAILED the real feed — see the HEAD-vs-GET lesson below; IN stays 16 KB and the failure line stays ~45.5 K, which is why the storm floor is 46 K.) Genuine CDN cert flakes can still happen — but when the log says "PSA signature verification failed", read "out of memory" first. (The upstream bug — unchecked `psa_hash_compute` + misleading message in IDF 6.0.2 — appears unreported; esp-idf #18640 is a different HW-SHA variant.)
- **HEAD-probe stress validates the handshake, not the body path**: `SSL_IN_CONTENT_LEN=8192` passed 148/148 alternating ESPN/Google HEAD handshakes with the memory-pressure failure line walking down exactly the 8 KB saved — a textbook "validated" result. The production GET then died right after a clean handshake (`esp_tls_conn_read error`, http -1): Akamai serves the scoreboard body in 16 KB records, so the IN buffer must stay 16384 no matter how pretty the handshake soak looks. Probe the transport with the SAME message shape the product uses; a handshake-only soak certifies half the connection.
- **A persistent TLS connection parked across the idle gap is worse than reconnecting**: esp_http_client keep-alive is a within-burst win only. The first version kept one client alive forever, and the open session parked ~22 KB (IN/OUT record buffers + TLS context) for the whole 15-minute refresh gap — cycle-start heap fell 46 K → 24 K and the 25 K safety floor reboot-looped the board every ~60 s (caught in the 45 s soak, thank you). Now the worker calls `espn_api_conn_release()` before every sleep (and every backoff): reuse covers the 4 s-paced request chains (day-walk, slate hunt, pre-warm = ONE handshake each), and the pool holds nothing while idle. Two artifacts to read logs with: the instant heap read right after release looks alarmingly low (lwIP closes sockets lazily — the ~29 K returns within seconds, visible at the next cycle start), and one connection per burst still leaks the known ~200 B — the storm floor turns that drift into roughly one self-healing restart a week instead of storm hours.
- **A silent NVS miss reads as corruption**: `svc_blob_load`'s "entry absent / length mismatch" return logged nothing, so a boot with `cache 0` after a soak (whose flash reset landed inside the previous persist's NVS write, clipping the entry) looked like a validation bug for a debug session. It logged `no stored <league> scores yet` from then on — self-healing paths still deserve a line saying why they self-heal.
- **Swap the feed source under an existing consumer base by remapping at the PARSE boundary**: the ESPN scoreboard's ids are a different namespace from the balldontlie ids the logo/venue tables, `game_logo` dispatch, and NVS blobs all speak, so `espn_api.finish_event` translates (generated `pro_team_ids.c`, join = full name, cap 30/13, unmapped→0→ring). Every consumer kept working untouched — and old balldontlie blobs stayed valid without a magic bump (same struct, same id space). Had the raw ESPN ids leaked downstream, the namespaces overlap (ESPN 17 = BKN, balldontlie 17 = POR) and the logo tables would have drawn *wrong teams* silently — the same trap class as picking a logo by the number.
- **`cards_loaded_cb`'s poke cannot fire at boot — by design**: the cards container is seeded with the create-time "No games to display" label, so the empty-container check (built for the detail view freeing the page) is false at first SCREEN_LOADED. Chasing "why doesn't the board re-poke right after the boot render" wastes evenings; the boot paint comes from `svc_cache_load`'s early render or cycle 1 anyway.
- **A never-returning diagnostic entry point GCs your app — the flash number lies**: `svc_tls_stress` ends in `for(;;)`, so GCC proves everything after its call site in `svc_task` unreachable, the linker GC chain drops `cards_screen_show_games` → `add_card_logo` → `game_logo` → the whole 323 KB logo rodata (+feed/render code) — a stress binary came out **363 KB** under the production one built minutes earlier with the same sdkconfig. Flash numbers must come from a hook-free production-shape build; hunt such a gap with `size -A` on the ELF (`.flash.rodata` smaller than the logo table alone = art got GC'd), not by diffing .bin sizes. Retroactively explains the old "clean binary with wolfSSL = 1,518,912 < production" anomaly too.
- **An allocator hook must pair foreign frees, not reject them**: `mbedtls_platform_set_calloc_free` catches the *free* side of allocations made through compile-time bindings it cannot see — ESP32's ROM mbedtls glue (`mbedtls_rom_osi.c`) binds `._mbedtls_calloc` to `esp_mbedtls_mem_calloc` (system heap), and those ~3 ptrs/handshake are freed via the runtime hook. Rejecting them (range check) is corruption-safe but leaks ~1.3 KB per handshake and mimics the very storm the arena exists to kill; the correct handling is `free()` for out-of-range pointers (single internal heap). General rule for any global allocator swap: assume mixed-lineage pointers and log + pair, never silently drop.
- **Dead code turns never-written statics into `.rodata` — flash-GC's RAM twin, and only a volatile STORE stops it**: with `svc_tls_stress` swallowing the worker, every writer of the pager arrays (`s_cache`, `s_page_box`, `s_api_page`, `s_blob`) became unreachable, and GCC **promoted the zero-init arrays to `.rodata`** (+35 KB flash, DRAM shape silently gone) — the stress probes then ran with ~35 KB more free heap than production has, quietly invalidating a wall-crossing run. Reading the arrays does not fix it: plain reads fold (dead-branch form changed nothing), and `volatile int x = arr[0] + ...` puts the volatile on the *destination*, not the load. Pin with `*(volatile uint32_t *)&arr[0] = 0;` (zero preserves .bss semantics). Verify with the linker map, grepping the name loosely — the map **wraps** long entries (name on one line, address on the next, so `^ \.bss\.name` misses half of them) — `size -A`/`readelf -SW` cannot see per-variable sections at all (merged by the linker).
- **A heap-level floor is only a statement about the allocator it was measured under**: both TLS-storm floors became lies the moment the mbedTLS arena installed — the pool sits *below* the 46 K band permanently (the arena is .bss), so the 48 K pre-warm gate deferred the warm forever (feature silently dead) and the 46 K storm floor would **reboot-loop any plain internet outage** (its cannot-reboot-loop guarantee rested on post-boot heap ~54 K). Gate such floors on the allocator mode (`mbedtls_arena_active()`), not on heap level; and when sizing a static pool that lowers the baseline, re-audit every constant that reads the baseline. Related UX corollary the same change forced: a once-per-boot warm must trigger on a *connected* success, not merely a successful cycle — an offline boot renders the NVS snapshot as a success and would burn the single slot on doomed requests.
